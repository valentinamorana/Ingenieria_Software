REVISIÓN 11/06 — SIMPLIFICACIÓN DE PERMISOS (FAMILIAS RETIRADAS)
---------------------------------------------------------------
  • Los PERMISOS (patentes) son un CATÁLOGO FIJO: no se crean/editan/eliminan
    desde la UI; solo se ASIGNAN a roles.
  • Los ROLES sí son administrables (crear / renombrar / eliminar / asignarles
    permisos u otros roles → rol-en-rol, que mantiene vivo el Composite).
  • Las FAMILIAS se ELIMINARON del modelo. La migración (en 01_Crear y 02_Actualizar):
      1) materializa las relaciones Rol → Patente alcanzables vía familias,
      2) borra las aristas que tocan familias,
      3) desactiva (Estado = 0) los nodos Familia.
    Los permisos EFECTIVOS de cada rol no cambian; el árbol queda Rol → Patente
    (+ Rol → Rol para la herencia entre roles).
  • El CAMBIO DE ROL de un usuario se hace desde Administrar → Administración de
    Usuarios → Cambiar rol (solo Administrador; protege al último admin activo).

QUÉ CAMBIÓ EN LA CONSOLIDACIÓN (v8)
-----------------------------------
Se limpió la jerarquía para que NO haya roles duplicados ni sueltos:

  • Inventario — dos operadores con responsabilidades CLARAS + un jefe que los hereda:
      - OperadorLogistico    → pedidos / despacho
      - OperadorDeInventario → mantenimiento / limpieza de prendas (stock)
      - GerenteInventario ⊃ AMBOS operadores
    Antes "Operador de Inventario" y "Operador Logístico" eran casi idénticos (los dos
    sólo veían "Ver Pedidos Realizados") y "Encargado de Stock" los englobaba.

  • Comercial — un solo jefe del área:
      - GerenteComercial ⊃ Vendedor
    Se retiró "Supervisor" (se confundía con GerenteComercial).

ROLES RETIRADOS (Estado = 0, ya no se ofrecen al crear usuarios):
  • Supervisor          → sus usuarios se migran a GerenteComercial.
  • EncargadoDeStock    → sus usuarios se migran a OperadorDeInventario.
  • ControladorDeStock  → sus usuarios se migran a OperadorDeInventario.

Todo se seedea de forma idempotente en:
  • BD/01_Crear_BaseDeDatos.sql      (instalación limpia)
  • BD/02_Actualizar_BaseDeDatos.sql (bases existentes)
mediante la tabla PermisoRelacion (única fuente de verdad del árbol). El bloque
"CONSOLIDACIÓN DE ROLES (v8)" va al final de las migraciones de roles y deja el árbol
en el estado objetivo sin importar el estado previo.


LAS "VISTAS" (PATENTES) DEL SISTEMA
-----------------------------------
Cada vista es un ítem de menú (patente) que habilita una pantalla:

  mnuUsuarios            → Gestionar Usuarios        (ABM de usuarios + claves/integridad)
  mnuAuditoria           → Ver Auditoría             (Bitácora del sistema y de negocio)
  mnuPrendas             → Ver Prendas               (catálogo de prendas)
  mnuOutfits             → Ver Outfits               (combinaciones)
  mnuCategorias          → Ver Categorías            (categorías de prendas)
  mnuStock               → Gestionar Stock           (control de stock)
  mnuClientes            → Gestionar Clientes        (ABM de clientes)
  mnuPlanSuscripciones   → Planes de Suscripción     (ABM de planes)
  mnuPedidosVenta        → Realizar Ventas           (alta de pedidos)
  mnuPedidosRealizados   → Ver Pedidos Realizados    (despacho / seguimiento)


JERARQUÍA VIGENTE (⊃ = "contiene / hereda de")
----------------------------------------------

  GerenteComercial  ⊃  Vendedor
  GerenteInventario ⊃  OperadorLogistico
  GerenteInventario ⊃  OperadorDeInventario
  Auditor           (rol plano, sin hijos)
  Administrador     (acceso total, no se modela por patentes)


ROLES Y SUS VISTAS EFECTIVAS
----------------------------

▸ Administrador
    VE: TODO (las 10 vistas) + módulos de seguridad (Backup, Diagnóstico de Integridad, Usuarios).

▸ Auditor
    Propias:   Ver Auditoría
    VE: Ver Auditoría
    (Rol transversal de solo lectura para control/auditoría.)

▸ Vendedor
    Propias:   Ver Prendas, Gestionar Clientes, Planes de Suscripción, Realizar Ventas
    VE: las cuatro de arriba.

▸ GerenteComercial   (⊃ Vendedor)
    Propias:   Ver Pedidos Realizados
    Heredadas: Ver Prendas, Gestionar Clientes, Planes de Suscripción, Realizar Ventas
    VE: Ver Prendas, Gestionar Clientes, Planes de Suscripción, Realizar Ventas,
        Ver Pedidos Realizados
    (Jefe del área comercial.)

▸ OperadorLogistico
    Propias:   Ver Pedidos Realizados
    VE: Ver Pedidos Realizados
    (Se encarga de los pedidos y el despacho.)

▸ OperadorDeInventario
    Propias:   Ver Prendas, Gestionar Stock
    VE: Ver Prendas, Gestionar Stock
    (Se encarga del mantenimiento / limpieza de las prendas y del stock.)

▸ GerenteInventario  (⊃ OperadorLogistico + OperadorDeInventario)
    Propias:   Ver Categorías, Ver Outfits
    Heredadas: Ver Pedidos Realizados, Ver Prendas, Gestionar Stock
    VE: Ver Pedidos Realizados, Ver Prendas, Gestionar Stock,
        Ver Categorías, Ver Outfits
    (Jefe del área de inventario: ve lo de los dos operadores + categorías/outfits.)

CÓMO PROBARLO / DEMOSTRARLO
---------------------------
1. Correr 02_Actualizar_BaseDeDatos.sql (o 01 en instalación limpia).
2. En "Gestión de Usuarios", crear un usuario con rol GerenteInventario.
3. Iniciar sesión con ese usuario: el menú muestra exactamente sus 5 vistas
   (Categorías + Outfits propias + las heredadas de los dos operadores).
4. En "Gestión de Permisos":
   • el árbol de la derecha muestra la composición recursiva del rol elegido;
   • el toggle "Ver todos los roles" muestra el bosque completo de un vistazo;
   • "Embeber" permite anidar/desanidar roles en vivo.

NOTA: el motor resuelve los permisos RECURSIVAMENTE y deduplica los que llegan
por varios caminos (BLL.Familia.ObtenerPermisosEfectivos). La asignación de un
rol dentro de otro valida que NO se genere dependencia circular (RF-12/13).
